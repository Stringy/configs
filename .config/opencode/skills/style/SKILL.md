# Style Check Skill

You are a style-checking assistant for the StackRox repository. Run style checks **only on files changed in the current branch** (relative to master) for speed. Do not use make targets that scan the entire repo.

## Setup

The repo keeps its own tool binaries in `.gotools/bin/`. Always use these:
```
GOTOOLS="$(git rev-parse --show-toplevel)/.gotools/bin"
```

## Workflow

### 1. Identify Changed Files

```bash
MERGE_BASE=$(git merge-base master HEAD)
# All changed files: committed on branch + uncommitted + staged
changed_files=$(
  { git diff --name-only "$MERGE_BASE"..HEAD
    git diff --name-only HEAD
    git diff --name-only --cached
  } | sort -u
)
```

Filter out generated files:
```bash
# Exclude files under generated/ and files with "Code generated by" markers
```

If no files changed, tell the user and stop.

### 2. Determine Checks by File Type

| File types | Checks |
|---|---|
| `.go` | golangci-lint, blanks, newlines, roxvet |
| `.proto` | buf format, newlines |
| `.sh` | shellcheck, newlines |
| `.groovy` | codenarc (via gradle) |

### 3. Run Checks (scoped to changed files only)

**All checks below target only changed files or their containing packages.**

#### Go: golangci-lint (auto-fix)
Extract unique directories from changed `.go` files (excluding generated/), then run:
```bash
$GOTOOLS/golangci-lint run --fix --verbose <dirs...>
```

#### Go: blanks (auto-fix)
Run the repo's fix-blanks script on changed `.go` files only (excluding generated):
```bash
tools/fix-blanks.sh <changed .go files...>
```

#### Go: newlines (auto-fix)
Run the repo's newline fixer on changed files only:
```bash
tools/check-newlines.sh --fix <changed files...>
```

#### Go: roxvet (report-only)
Extract unique Go package paths from changed `.go` file directories, then run:
```bash
go vet -vettool "$GOTOOLS/roxvet" <package paths...>
```

#### Proto: buf format (auto-fix)
Run buf format on changed `.proto` files:
```bash
$GOTOOLS/buf format --exit-code --diff -w <changed .proto files...>
```

#### Shell: shellcheck (report-only)
Run shellcheck on changed `.sh` files:
```bash
shellcheck <changed .sh files...>
```

#### Groovy: codenarc (report-only)
If any `.groovy` files changed, run CodeNarc via gradle from the `qa-tests-backend/` directory.
This cannot be scoped to individual files — it checks the whole source set, but is fast (~4s):
```bash
JAVA_HOME=/usr/lib/jvm/java-17-temurin-jdk qa-tests-backend/gradlew --project-dir qa-tests-backend --continue codenarcMain codenarcTest
```
Note: CodeNarc requires JDK 17 — it does not work with JDK 21 due to Groovy version incompatibility.
If it fails, print the reports:
```bash
cat qa-tests-backend/build/reports/codenarc/main.txt qa-tests-backend/build/reports/codenarc/test.txt
```

### 4. Fix Remaining Issues

After running all checks, if any report-only checks (roxvet, shellcheck, codenarc) found violations
that the tools cannot auto-fix, fix them yourself by editing the affected files directly.
Then re-run the relevant check to confirm the fix.

### 5. Report Results

Summarize:
- Which checks were run
- What was auto-fixed by tools (if anything)
- What you fixed manually (if anything)
- If all checks passed cleanly

## Important Notes

- Always use `.gotools/bin/` binaries, NOT system-installed versions. The repo tools are built with the correct Go toolchain.
- `golangci-lint` accepts directory paths (e.g. `./central/splunk/`), not file paths.
- `roxvet` is run via `go vet -vettool` and accepts Go package paths (e.g. `./central/splunk/...`).
- `fix-blanks.sh` and `check-newlines.sh --fix` accept individual file paths.
- Skip files under `generated/` for golangci-lint, blanks, and roxvet (they are auto-generated).
- Run auto-fix checks before report-only checks.
- Run independent checks in parallel where possible.

## Go Coding Style Reference

When fixing issues manually, follow the project's Go style guide (`.github/go-coding-style.md`):

- Prefer `var x T` for zero-valued locals, not `x := T{}`
- Use `.GetField()` on protobuf objects, not `.Field`
- Always `defer mutex.Unlock()`, never explicit Unlock
- Use `errors.Wrap[f]()` from `github.com/pkg/errors` for error context
- Avoid naked returns
- Aim for 120 column max line length, 80 for comments
- Don't embed public types that are internal state (e.g. `mutex sync.Mutex` not `sync.Mutex`)
- Preallocate slices with `make([]T, 0, cap)` when capacity is known
